Data visualisation is popular and the demand keeps growing. There is even a separate profession, the infographics designer, whose job is to draw beautiful, clear charts. But graphic editors don't always give enough flexibility and automation for routine tasks, and the way to optimise the work, as ever, is with code — in this lesson, with the D3.js library.

It is fashionable now to talk about Data-Driven Design, and D3 in fact stands for Data-Driven Documents, the idea being to bind data to the DOM. Let's get the limitations out of the way first: D3 does not support old browsers, it runs on the client, so you cannot hide the original data — if you need to hide it, draw an image or use Flash (which is not as bad as it sounds). Otherwise, D3 lets you build stunning interactive infographics. The available methods are Bundle, Chord, Cluster, Force, Histogram, Pack, Partition, Pie, Stack, Tree, and Treemap — not all the chart types you might ever need, but enough for most tasks.

## Setting up

To start, download D3 and drop the library into a sub-folder of the project, or use the lightweight build, and then it is time to read the documentation. Without UTF-8 the browser cannot parse the data for D3, so make sure the encoding is right everywhere and that you haven't lost the `<meta charset="utf-8">`. The folder hierarchy should come out like this:

```
project-folder/
   d3/
      d3.v3.js
      d3.v3.min.js (optional)
   index.html
```

## Loading the data

Since we are visualising real data, the first question is where to get it. There should be a JSON or GeoJSON file, though a CSV will do. To visualise it, we bind the incoming data to DOM elements (D3 works with the JS DOM) using `d3.select("body")`; you can also use `d3.selectAll("span")`, which differs in that it returns every match for the element named — so the first returns a single `body`, the second returns all `span` elements even if there are a thousand, and if no `<span>` is found, an empty value is returned. Loading a CSV uses:

```js
d3.csv("data.csv", function(data) {
    console.log(data);
});
```

`d3.csv()` is a global object. The empty function is a callback — used to pass code as one of the parameters of another piece of code, firing after the CSV is loaded into memory, which guarantees that `d3.csv()` exists by the time the callback runs. A JSON file is loaded and handled in exactly the same way:

```js
d3.json("waterfallVelocities.json", function(json) {
    console.log(json); // Log output to console
});
```

## Binding data to the DOM

With the data loaded, all that remains is to use it. D3.js uses a "fluent interface" — code written as a chain of methods, where each method is called on the object the previous one returned, so each call sits on its own line. You select a particular dataset like this:

```js
var dataset = [ 5, 10, 15, 20, 25 ];

d3.select("body").selectAll("p")
    .data(dataset)
    .enter()
    .append("p")
    .text(function(d) { return d; });
```

Now we have variable data for which we create DOM elements, removing and adding elements as the data count changes. The interesting part is **`.enter()`**, which creates a new element bound to the data — if there are twenty little people in the data, twenty DOM elements are created — after which **`.append("p")`** takes the freshly created elements and adds them as `<p>`. The functions `select()`, `append()`, and `classes()` are methods of the `selectAll` object, and the result returned is an object of type `select`. It is also important to know about `update()` and `exit()`: **`exit()`** identifies and matches the elements that have no data and must be removed, while **`update()`** identifies the DOM elements that already have data.

![The enter / update / exit data-join](https://your-scorpion.ru/wp-content/uploads/2074/03/3.png)

The pattern, then, is fairly standard: apply a class to a `div` and change its CSS properties through that class, using the `selection.attr()` method. Here it is important to understand the difference between **`attr()`** and **`style()`** — the latter applies CSS changes directly to the element, while `attr()` applies changes to the DOM attributes. That distinction matters, because CSS itself is simple and can be learned in fifteen minutes, but finding a convenient way to organise it takes years — which is where Styled Components, or CSS-in-JS, come to the rescue.

## From div to SVG

Working with Canvas is interesting, but working with SVG is more interesting still. Instead of creating a `div` we can create a `rect`, forming an SVG; to select every `rect` in the SVG we use `selectAll`. We add a `rect` to the DOM, bearing in mind that it must carry the attributes `x`, `y`, `width`, and `height` — in place of "left" and "top" for HTML elements, SVG sets the "x" and "y" coordinates. So this lets you set a rectangle 150 px tall, 60 px wide, inset 60 from the left and 10 from the top, black by default (later, of course, these will need to change with the data we load):

```js
svg.append("rect")
    .attr("height", "150")
    .attr("width", "60")
    .attr("x", "60")
    .attr("y", "10");
```

The same can be written with an attribute object:

```js
svg.append("rect").attr({ "x": "60px", "y": "10px", "width": "60px", "height": "150px" });
```

## A minimal example

With what we now know, here is the minimal example:

```js
var circles = svgContainer.selectAll("circle") // select all the SVG circles
    .data(circleRadii)  // bind the data to the selected circles
    .enter()            // select the virtual, missing elements
    .append("circle");  // add the elements
```

A live version is on CodePen: [the first D3 pen](https://codepen.io/Yourscorpion/pen/aLVwGV/).

We have drawn a single lonely vector square, which is rather dull. SVG can hold not only squares but circles, lines ([paths](https://developer.mozilla.org/en-US/docs/Web/SVG/Tutorial/Paths)), and text. ## Placing labels around a circle

Adding circular labels to the second example comes down to finding the radian angles — the cosines, tangents, and sines of trigonometry.

![Trigonometric relationships in a right triangle](http://your-scorpion.ru/wp-content/uploads/2017/12/Slice-2-20.png)

Any triangle divides into right triangles, which are easier to work with. To refresh the school basics: if the hypotenuse `B` is unknown but the triangles are geometrically similar, the formula follows from that similarity.

![Similar-triangle ratios](http://your-scorpion.ru/wp-content/uploads/2017/12/Group-1.png)

In the left triangle you can apply the Pythagorean theorem, where the sum of the squares of the legs equals the square of the hypotenuse, so sin²α + cos²α = 1.

![Pythagorean identity on the unit circle](http://your-scorpion.ru/wp-content/uploads/2017/12/Slice-2-20-1.png)

From there, sin α = cos β = cos(90° − α) and cos α = sin β = sin(90° − α). Mapping this onto computing the position of the headings around the diagram: along the X and Y axes, cosine and sine track the position of the needed point on the circle's edge.

![Cosine and sine placing a point on the circle's edge](http://your-scorpion.ru/wp-content/uploads/2017/12/IMG_5890.png)

Now to compute some values.

![A worked right-triangle example](http://your-scorpion.ru/wp-content/uploads/2017/12/Untitled-1.png)

14² = 196, 9² = 81, 196 + 81 = 277, and the square root of 277 is 16.6, so tan α = cot β = 9⁄14, cot α = tan β = 14⁄9, cos α = sin β = 14⁄16.6, and sin α = cos β = 9⁄16.6. The calculation is simple enough: an angle of 30 equals 0.523598 radians, whose cosine is 0.866. Checking:

```js
var A = 30; // angle 0–360
with (Math) {
    n = cos(A * PI / 180); // PI is 3.14, A is the variable, 180 for the formula's angle notation
}
console.log(n);
```

## Anti-aliasing, and the move from Flash

Trouble getting clean anti-aliasing on charts ported from Flash is a common complaint. Flash was fast and vector-based, with very good mathematics that let you control the degree of vector smoothing: when a line passed through pixels, Flash determined from sixteen points which parts of the shape fell into a pixel and computed the average colour accordingly. Canvas 2D, by contrast, computes the geometric area, which is fine for a single shape but produces bugs where two shapes intersect.

![Anti-aliasing difference where shapes intersect](http://your-scorpion.ru/wp-content/uploads/2021/02/Group-16.png)

It is worth making peace with a simple idea: when HTML5 began to be pushed (Canvas 2D and WebGL, the latter based on mobile ES), it lagged Flash badly on features, and it still does. The hope was that the big developers would build the missing pieces themselves, but everyone had to port projects off Flash quickly, and the result is a zoo of Phaser, CreateJS, and PixiJS — but without the great mathematics. Blur, for example, is done differently on the CPU and the GPU; look at the square blur in Figma.

## Choosing a library for a huge network map

For a large network-map visualisation there are many libraries; I would choose among D3 (with WebCola, on Canvas), GoJS, JointJS, Cytoscape, G6 (AntV), ArcGIS, yWorks, and vis.js. But what really matters is performance. WebGL has a notion of *far lands*: numbers in JavaScript are normally double-precision, but those sent to a shader may carry coordinates in single-precision float, and inside the shader the precision is low, so floating-point numbers must stay small. A shader is only the final link of graphics programming and so is often not very flexible, and different graphics cards compute differently — a big pain of WebGL, especially on mobile. A handy command for debugging is:

```
TASKKILL /IM chrome.exe /F
cd "C:\Program Files (x86)\Google\Chrome\Application"
chrome.exe --disable-gpu-vsync
```

It is useful to add `--disable-frame-rate-limit` as well, or to go into the NVIDIA Control Panel or Catalyst Control Center and turn off VSync, or, the old-fashioned way, use `setInterval`.
